# 农餐馆 · 农大智慧餐厅

> 从现场菜单到营养参考，把每一个窗口看得明白，把这一餐选得轻松。

中国农业大学东区公一食堂（公寓一食堂）的菜品、营养、实时排队和同学点评，做成一个手机也能用的网页应用。

**这是 2026 农客松（AgriHackathon）主赛道参赛作品。** 初赛 48 小时赛程：2026-11-20 18:00 — 2026-11-22 18:00。

## 现在能做什么

| 能力 | 说明 |
|---|---|
| **菜品与营养** | 6 个窗口、43 道菜，每道菜有价格、参考份量、每 100g 的热量 / 蛋白质 / 脂肪 / 碳水 / 膳食纤维；支持半份 / 标准份 / 1.5 份换算 |
| **共享排队雷达** | 同学上报窗口前的人数和时间，后端取最近 20 分钟内最多 5 条上报的中位数，折算预计等待分钟数；20 分钟无新上报会标灰提示「待更新」 |
| **真实点评** | 1–5 星 + 200 字文字，按菜品聚合平均分与点评数；同一设备 24 小时内可修改自己的点评 |
| **智能配餐** | 按均衡 / 高蛋白 / 减脂 / 素食四个目标，从真实菜品里配一餐，并优先避开正在排队的窗口；可整餐加入餐盘 |
| **今日餐盘** | 选份量、算本餐热量与三大营养素，数据存在本地，刷新不丢 |
| **现场菜单相册** | 14 张 2026-11-21 公一食堂现场实拍，菜名和价格可回溯到照片 |

## 数据诚实性

- 18 号窗口（低脂美食新风尚）的营养数值**录入自窗口现场公示表**，按每 100 克记录。
- 其余窗口的营养为 **AI 估算**，根据菜名、常见食材与烹饪方式推算，不是检测值。
- 每张菜品卡右上角都标了数据来源（`窗口公示` / `AI估算`），详情页也写明。
- 初始点评和排队数据为空，由真实用户产生；应用里没有内置假点评、假排队或假按钮。

## 快速开始

前置：Node.js 18+（开发机为 v24）。**零 npm 依赖，不需要 `npm install`。**

```text
方式一：Windows 双击项目根目录的 start.bat
方式二：命令行
  cd ganfan-radar
  node server.js
```

浏览器打开 <http://localhost:3000>。端口可用环境变量覆盖：

```bash
# macOS / Linux / Git Bash
PORT=8080 node server.js

# PowerShell
$env:PORT=8080; node server.js
```

手机同 Wi-Fi 演示：`ipconfig` 取本机 IPv4，手机访问 `http://<IPv4>:3000`，首次运行在 Windows 防火墙弹窗中允许「专用网络」。详见 [docs/部署指南.md](docs/部署指南.md)。

## 微信小程序

仓库内附带一个原生小程序客户端（`miniprogram/`），与网页版共用同一套后端，排队和点评是同一份数据。

- 打开方式：微信开发者工具导入 **仓库根目录**（`project.config.json` 已指定 `miniprogramRoot`）
- AppID：填自己的，或先用测试号
- 开发期在「详情 → 本地设置」勾选「不校验合法域名」
- 小程序首页右上角 **⚙** 设置服务器地址：模拟器填 `http://localhost:3000`，真机填电脑局域网 IP
- 功能：食堂选择（公一已上线，公二/公三显示待录入且不可选）、排队速览、目标配餐（避开排队与最近吃过的菜）、菜单搜索筛选、菜品详情、点评与点赞、好评榜、碳排粗估、干饭积分
- 正式上线需要 HTTPS + 已备案域名 + 小程序后台配置 request 合法域名

完整步骤与平台限制见 [docs/小程序与服务器.md](docs/小程序与服务器.md)。

## API

所有接口返回 JSON，错误统一为 `{ "error": "..." }`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/menu` | 完整菜单：食堂、窗口、菜品、照片元数据 |
| GET | `/api/summary` | 当前排队 + 各菜评分 + 统计，一次拉全 |
| GET | `/api/queues` | 各窗口排队状态，按预计等待升序 |
| POST | `/api/queues` | 上报排队 `{windowId, people, deviceId}`；同设备同窗口 3 分钟限一次 |
| GET | `/api/dishes/:id` | 菜品详情 + 最近 50 条点评 |
| POST | `/api/dishes/:id/reviews` | 发布点评 `{rating, text, author, deviceId}`；同设备 24 小时内覆盖 |
| GET | `/api/leaderboard?type=rating\|empty` | 好评榜 / 最空窗口榜 |
| GET | `/api/stats` | 菜品、点评、当日上报等统计 |
| GET | `/api/health` | 健康检查 |

排队等待时间：`max(0, round(人数中位数 × 0.4))` 分钟。

## 技术要点

- **零第三方依赖**：只用 Node 内置模块，断网也能跑，现场演示不受网络影响。
- **原子写入**：运行数据先写 `data/db.json.tmp` 再 `rename`，并串行化写入，避免并发写坏文件。
- **静态资源防护**：`decodeURIComponent` + `normalize` 后校验目标仍在 `public/` 内，拦截路径穿越。
- **限流与防刷**：同设备同窗口 3 分钟一次上报；同设备同菜品 24 小时内只保留最新点评。
- **XSS 防护**：点评、昵称、菜名一律转义后再插入 DOM。

## 队友成果的整合

- 前端视觉与菜品营养数据来自队友交付的静态站点（原名「食刻」，整合后统一命名为「农餐馆」）；我把它改造成由后端下发菜单，并保留原有渲染、筛选、餐盘和相册逻辑。
- 共享排队、点评、智能配餐中的"避开排队窗口"逻辑、后端服务与端到端验收由本仓库完成。
- 数据提取使用文本解析（`tools/extract-teammate.js`），不执行第三方代码。
