# 决赛路演：用小程序演示怎么排

> 场景：11-29 东校区招聘大厅，路演 5 分钟 + 答辩 2 分钟，现场大屏 + 手机。
> 目标：**评委看大屏，你操作真机**；小程序和网页版共用一套后端，两边可以互相印证。

---

## 一、先定原则

1. **不要让评委现场装体验版**。体验版只有「体验成员」能打开，加人要走后台；现场网络也不允许。
2. **手机只负责「被看到」**。画面投到大屏，评委不需要碰。
3. **演示必须能在没有外网的情况下跑完**。会场 Wi-Fi 大概率有认证页或 AP 隔离，别赌。

结论：**笔记本当服务器 + 手机连同一个热点 + 手机画面投到大屏**。

---

## 二、网络：三套方案，按可靠性排

| 方案 | 怎么做 | 依赖 | 推荐度 |
|---|---|---|---|
| **A. 手机热点 + 笔记本** | 手机开热点 → 笔记本连上 → 笔记本跑 `node server.js` → 手机小程序 ⚙ 填 `http://<笔记本IP>:3000` | 无外网，只要热点 | ★★★★★ |
| B. 会场 Wi-Fi + 笔记本 | 笔记本和手机连会场网，地址同上 | 会场允许设备互访（常被隔离） | ★★ |
| C. 云服务器 + 隧道 | 体验版默认地址指向线上隧道 | 外网 + 隧道进程没挂 | ★（只当备份） |

方案 A 的操作：

1. 手机开热点（名字随意，密码设一个）
2. 笔记本连这个热点，双击项目根目录的 **`start-demo.bat`**
3. 窗口里会打印两行地址，记下形如 `http://10.x.x.x:3000` 的那条（和 Wi-Fi 网卡对应的一条，`172.19.x` 是 WSL 虚拟网卡，忽略）
4. 手机微信打开体验版 → 右上角「…」→「开发调试」→ 打开调试（小程序会重启）
5. 小程序首页右上角 **⚙** → 填第 3 步的地址 → 保存
6. 首页出现 6 个窗口卡 = 通了

> 第一次连不上，九成是 Windows 防火墙拦了 Node。当前这台机器是「公用」网络配置（默认阻止入站），而且**没有 node.exe 的入站规则**，所以手机过不来：
>
> - **最省事**：右键 `start-demo.bat` → **以管理员身份运行**一次，脚本会自动放行 TCP 3000（规则保留，以后不用再点）
> - 手动等效命令（管理员 PowerShell / CMD）：
>   ```
>   netsh advfirewall firewall add rule name="nongcanguan-3000" dir=in action=allow protocol=TCP localport=3000
>   ```
> - 验证：手机浏览器打开 `http://<IP>:3000/api/health`，能看到 `{"ok":true...}` 就通了

## 三、投屏：三选一

### 1. 系统投屏 / scrcpy（画面最干净，优先）

- **Android**：数据线连电脑 → 电脑装 [scrcpy](https://github.com/Genymobile/scrcpy) → `scrcpy --max-size 1024`，手机画面即窗口，操作电脑鼠标或直接摸手机都行
- **iPhone**：Mac 用 QuickTime「新建影片录制 → 选 iPhone」；Windows 用「幕享 / 爱思投屏」等，或 AirPlay 到支持投屏的盒子
- 优点：大屏上就是一台手机的样子，评委一眼看懂「这是小程序」

### 2. 微信开发者工具「真机调试」（官方、最稳）

1. 开发者工具打开本项目 → 工具栏点「真机调试」
2. 手机微信扫码 → 手机上打开小程序
3. 电脑左侧出现手机画面，可实时操作

优点：不装第三方软件；缺点：画面旁边是 IDE，观感偏「开发中」。适合投屏方案临时失效时顶上。

### 3. 预录视频（兜底，必须有）

路演前用手机自带录屏，按下面的脚本完整录一遍（2–3 分钟），存到手机和电脑各一份。网络挂、投屏挂、小程序白屏，直接播视频，嘴上继续讲——**这是唯一不会翻车的方案**。

## 四、5 分钟路演脚本（小程序版）

> 0:00–0:40 讲问题，0:40–4:20 演示，4:20–5:00 收尾。演示全程在手机上完成，大屏同步。

| 时间 | 你的操作 | 你要说的话 |
|---|---|---|
| 0:00–0:25 | 停在首页 | “食堂最大的问题是看不见：今天卖什么、哪个窗口不排队、这道菜多少热量，全靠走到跟前才知道。” |
| 0:25–0:40 | 手指划过顶部三个食堂 | “公一已经上线，6 个窗口 43 道菜；公二公三我们在页面里写「待录入」，没有编数据。” |
| 0:40–1:20 | 点 18 号窗口卡 → 进菜品列表 → 点开一道菜 | “窗口先出现、菜品后出现，这是学生真实的决策顺序。点开一道菜，每 100 克的营养、按份量换算、数据来源都写清楚。” |
| 1:20–1:50 | 点「加入今日餐盘」，再点 ♥ 收藏 | “加进餐盘，这一餐的热量和蛋白质实时累计；喜欢的菜收藏，下次不用再翻。” |
| 1:50–2:20 | 回首页 → 点「盲盒随机」→ 抽一个 | “选择困难就交给盲盒，会避开最近吃过的。” |
| 2:20–2:50 | 点「今天怎么吃」→ 切「健身高蛋白」→ 换一餐 | “按目标配一餐，而且优先避开正在排队的窗口——把「吃什么」和「去哪吃」合成一个动作。” |
| 2:50–3:20 | 队友在自己手机上上报一次排队，回来点「排队」 | “这是共享状态：队友刚在楼下报了一次，我这边 60 秒内就看到 18 号窗口的人数和等待时间。20 分钟没人更新就自动标灰。” |
| 3:20–3:50 | 切到「我的」→ 指记录表 + AI 提醒 | “吃完点一下，个人记录里就有早中晚吃了什么、蛋白质多少，下面是按最近 7 天给的提醒。数据只存在自己手机上。” |
| 3:50–4:20 | 切回首页，停在窗口条 | “一套后端，网页版和小程序两个端，菜单、排队、点评是同一份数据。” |
| 4:20–5:00 | 停住 | “农餐馆：先看排队，再选一餐。谢谢。” |

答辩期（2 分钟）如果被问到「为什么不直接做个 App」：小程序零安装，同学在食堂门口扫一下就能用；网页版负责大屏和分享，后端完全复用。

## 五、开始前 30 分钟检查清单

- [ ] 笔记本充满电 / 插上电源，手机电量 > 50%
- [ ] 手机热点已开，笔记本已连上
- [ ] `start-demo.bat` **以管理员身份**跑过一次（放行 3000），浏览器 `http://localhost:3000` 能打开
- [ ] 手机体验版已「打开调试」，⚙ 地址已填并加载出 6 个窗口
- [ ] 队友手机也连热点、也开了调试、也能读到数据（用来现场上报排队）
- [ ] 投屏已连上，画面比例正常（手机竖屏，别拉伸）
- [ ] 预录视频在桌面上，播放器能打开
- [ ] 网页版地址/二维码准备好（展板或口头给评委）
- [ ] 关掉微信/系统通知，关掉自动锁屏

## 六、故障切换表

| 现场现象 | 30 秒内怎么处理 |
|---|---|
| 小程序首页「加载失败」 | 检查笔记本 `start-demo.bat` 窗口还在跑；⚙ 里的 IP 是否变了（换热点会变） |
| 手机连不上笔记本 | 换回方案 C（云端隧道），或直接播预录视频 |
| 投屏黑屏 / 掉线 | 换「真机调试」，或拔插 HDMI，同时嘴上继续讲 |
| 排队数据一直是「暂无数据」 | 让队友当场报一次；报不上就说“冷启动阶段，数据由用户产生” |
| 小程序白屏 / 报错弹窗 | 杀掉小程序重进；仍不行 → 预录视频 |
| 大屏分辨率导致字太小 | 手机投屏时把系统字体调大一档，或改用「真机调试」的放大视图 |

> 现场一定会有意外。**先说话，再修设备**——评委听的是价值，不是你的排障过程。

---

## 七、顺手准备好的两件东西

1. **展板/PPT 上放网页版二维码**：评委和同学用手机浏览器就能打开，不占体验成员名额。二维码指向当前线上地址即可。
2. **一段 90 秒的网页版录屏**：万一手机完全用不了，用笔记本演示网页版，讲法完全一致（见 `docs/演示脚本.md`）。

---

## 八、版本选择对照

| 用哪个 | 像不像真实用户 | 现场风险 | 结论 |
|---|---|---|---|
| **体验版（已上传 1.1.0）** | 最像 | 需要开调试、需要能连到你的服务器 | **主用** |
| 开发版（开发者工具预览码） | 像 | 二维码 25 分钟过期 | 不用 |
| 开发者工具模拟器 | 不像 | 无（但要登录 IDE） | 只在投屏失效时顶一下 |
| 网页版 | 另一种形态 | 无（同一后端） | 备用 + 分享 |
