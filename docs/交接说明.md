## 1. 一句话说清楚这是什么东西

「农餐馆」把中国农业大学**公一食堂**的现场菜单搬到线上：6 个窗口、43 道菜，每道菜有每 100g 的营养数据，可以按半份/一份/1.5 份换算；同学可以众包上报窗口排队人数，20 分钟内多条上报取中位数折算等待时间；吃完能 1–5 星点评；首页还有单菜盲盒、按目标配餐、14 张现场实拍、好评榜和干饭积分。

**一套后端，两个前端**：网页版（原生 HTML/CSS/JS）+ 原生微信小程序，共用同一份菜单、排队和点评数据。

## 3. 本地跑起来（30 秒）

```bash
cd ganfan-radar
node server.js          # 需要 Node 18+，不需要 npm install
# 浏览器打开 http://localhost:3000
```

Windows 也可以双击 `start.bat`。

**小程序**：微信开发者工具导入本目录（`project.config.json` 已配 `miniprogramRoot`），AppID 用 `wxdfa728b622c8eb73`；详情 → 本地设置 → 勾选「不校验合法域名」，并让 `miniprogram/config.js` 里的 `BASE_URL` 指向可访问的后端（本机 `http://localhost:3000`，真机要填电脑局域网 IP 或线上 HTTPS 地址）。

验收脚本：`node tools/e2e.js`，会用无头 Edge 走真实浏览器，跑 13 项断言（菜单渲染、搜索、点评、排队上报、配餐入餐盘等）。

## 4. 线上环境（重点看这一段）

| 项 | 值 |
|---|---|
| Demo（HTTPS） | <https://exports-getting-participant-parameters.trycloudflare.com> |
| 服务器 | 腾讯云轻量应用服务器，Ubuntu 24.04，公网 IP `62.234.118.40` |
| 应用目录 | `/opt/nongcanguan`（由 `/opt/nongcanguan-src` 的仓库副本安装） |
| 数据目录 | `/var/lib/nongcanguan/db.json` |
| 常驻方式 | systemd 服务 `nongcanguan`，监听 `127.0.0.1:3000`，`www-data` 身份运行 |
| HTTPS | 服务器上的 cloudflared 临时隧道（`tunnel --url http://127.0.0.1:3000`） |

**登录方式**：轻量云防火墙只放行了 80 / 443 / 8888 / 3389 / ICMP，**22 端口没开**，所以 ssh 连不上。请在腾讯云控制台用 **OrcaTerm 登录**，或「执行命令（TAT）」跑 shell——两者都是免密进 root。

> 服务器 root 密码在初赛期间通过聊天传递过，**接手第一件事就是改密码**（控制台 → 重置密码），并确认队内不要再在聊天里传明文。

常用运维命令（在 OrcaTerm / TAT 里执行）：

```bash
systemctl status nongcanguan           # 服务状态
journalctl -u nongcanguan -n 50        # 最近日志
curl -s http://127.0.0.1:3000/api/health
```

升级代码（拉取最新仓库并重装）：

```bash
cd /opt/nongcanguan-src && git pull
bash deploy/install.sh                 # 会重新复制代码到 /opt/nongcanguan 并重启服务
```

> 注意：`/opt/nongcanguan` 里那份是 11-22 安装的，**不含**后来加的 mp4 MIME 支持；重跑一次 `install.sh` 即可同步。

重启 HTTPS 隧道（当前没有做成 systemd，是 `setsid` 起的，服务器重启后会丢）：

```bash
setsid /usr/local/bin/cloudflared tunnel --url http://127.0.0.1:3000 --no-autoupdate \
  > /var/log/cft2.log 2>&1 < /dev/null &
sleep 15
grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" /var/log/cft2.log | sort -u | tail -1
```

**⚠️ 这个隧道的两个坑**：

1. `trycloudflare.com` 是 Cloudflare 的免费临时域名，**进程重启就会换一个域名**。换了域名后要同步改三处：ANS 的 Demo 地址、`miniprogram/config.js` 的 `BASE_URL`、`docs/部署指南.md` 第 0 节。
2. 建议接手后把它做成 systemd 服务（开机自启、挂了自己拉起来），单元文件可以直接用下面这份：

```ini
[Unit]
Description=cloudflared quick tunnel
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/cloudflared tunnel --url http://127.0.0.1:3000 --no-autoupdate
Restart=always
RestartSec=5
StandardOutput=append:/var/log/cloudflared.log
StandardError=append:/var/log/cloudflared.log

[Install]
WantedBy=multi-user.target
```

存成 `/etc/systemd/system/cftunnel.service` 后 `systemctl daemon-reload && systemctl enable --now cftunnel`。

如果决赛现场要更稳：用自有域名 + 命名隧道（`cloudflared tunnel login/create`），或者直接给服务器备案域名配 Nginx + certbot。

## 5. 数据与接口速查

**菜品数据**（`data/menu.json`）：`canteens`（公一 online / 公二·公三 pending）→ `windows`（6 个）→ `dishes`（43 道，含每 100g 热量/蛋白质/脂肪/碳水/纤维、价格、份量、照片 id、来源标记）。

**运行期数据**（`data/db.json`）：`reviews`（点评）和 `queueReports`（排队上报），服务端用「临时文件 + rename」原子写并串行化。**删掉这个文件就是清空所有点评和排队**——演示前想从零开始就删它。

**主要接口**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/menu` | 完整菜单 |
| GET | `/api/summary` | 各窗口排队 + 菜品评分聚合 |
| GET/POST | `/api/queues` | 读/报排队（最近 20 分钟、最多 5 条取中位数；同设备同窗口 3 分钟限流） |
| GET | `/api/dishes/:id` | 单菜详情 + 点评 |
| POST | `/api/reviews` | 发点评（1–5 星、≤200 字；同设备 24h 内覆盖） |
| POST | `/api/reviews/:id/like` | 点赞（按设备幂等） |
| GET | `/api/leaderboard`、`/api/stats`、`/api/health` | 好评榜、统计、健康检查 |

完整说明见 `docs/API.md`。

## 7. 踩过的坑（省得你重复踩）

1. **微信开发者工具 CLI 报 AppID 不存在**：游客 AppID 不行，要用正式 AppID；CLI 的「服务端口」默认关闭，需在工具设置里打开。
2. **小程序「加载失败」**：九成是后端没启动，其次才是域名/IP 不对。
3. **校园网手机连不上电脑 IP**：AP 隔离，改用隧道或云服务器。
4. **腾讯云防火墙没放行 3000**：所以服务只监听本地、由隧道对外；想让 `http://62.234.118.40:3000` 直接可访问，得在「防火墙」里加一条 TCP 3000 规则。
5. **系统服务不监听 80 的原因**：`www-data` 没有绑定特权端口的权限，改 `PORT=80` 会起不来（实测报 `EACCES`，服务一直 `activating`）；要 80 就得加 `AmbientCapabilities=CAP_NET_BIND_SERVICE` 或前面挂 Nginx。
6. **TAT 执行命令的中文/长文本**：编辑器里粘贴多行容易串行，建议单行命令 + `;` 串联。
