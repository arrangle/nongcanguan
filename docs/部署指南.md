# 部署指南

应用只有一个 Node 进程，零 npm 依赖。本机运行是**已经实测**的路径；其余方式标注了验证状态，请按现场条件选择。

## A. 本机运行（已验证）

```bash
cd ganfan-radar
node server.js
```

Windows 也可以直接双击 `start.bat`（会开一个命令行窗口并自动打开浏览器）。

浏览器访问 <http://localhost:3000>。

- 端口占用时：`PORT=8080 node server.js`（PowerShell：`$env:PORT=8080; node server.js`）
- 首次启动会自动创建 `data/db.json`（运行期点评与排队）
- 重置所有点评与排队：停止服务，删除 `data/db.json`，重启
- 断网可用：页面不引用任何外部字体、CDN 或图片

## B. 局域网访问（已验证端口可达）

适用场景：决赛现场多台设备同时试玩。

1. 启动服务（默认监听所有网卡）。
2. 查本机 IPv4：

   ```text
   Windows: ipconfig
   macOS/Linux: ifconfig 或 ip addr
   ```

3. 手机与电脑连同一个 Wi-Fi，浏览器打开 `http://<本机IPv4>:3000`。

本次实测：在开发机上用 `http://10.6.126.155:3999/api/health` 访问返回 200。

常见问题：

- **打不开**：Windows 防火墙首次会弹窗，勾选「专用网络」并允许；若已拒绝，到「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里放行 Node.js。
- **手机能开网页但接口失败**：确认没有开热点隔离 / AP 隔离；关掉手机代理。
- **IP 变了**：切换网络后 IPv4 会变，重新 `ipconfig`。

## C. 内网穿透（未验证，可选）

适用场景：评委不在同一局域网时需要公网访问。

可选工具：cpolar、花生壳、ngrok 等。通用流程（各平台界面不同，请以官方文档为准）：

1. 本机启动 `node server.js`（端口 3000）。
2. 在穿透工具里创建 HTTP 隧道，本地地址填 `127.0.0.1:3000`。
3. 把工具分配的公网地址发给评委。

注意：

- 免费隧道通常限速或有随机域名，演示前先自测。
- 公网暴露后，任何人都能写点评和排队；我们的限流按设备标识，挡不住恶意换设备。正式长期运行需要加账号体系与内容审核。

## D. 云服务器（未验证）

任何能装 Node 18+ 的 Linux 云主机都可以：

1. 上传整个 `ganfan-radar` 目录（含 `public/assets/photos`）。
2. 安装 Node 18+。
3. `node server.js`，用 systemd / pm2 常驻。
4. 安全组放行端口；建议前面挂 Nginx 并上 HTTPS。

注意：

- `data/db.json` 是本地文件，容器或云函数的临时文件系统**不会持久化**，不要直接部署到不保留磁盘的云函数。
- 需要长期运行时，给 `data/` 挂持久卷，并定期备份。

## E. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3000` | 监听端口 |
| `ADMIN_CODE` | 空 | 设置后，`POST /api/menu` 必须携带匹配的 `adminCode`；不设置则开发模式放行 |
