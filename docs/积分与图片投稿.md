# 积分与图片投稿

菜品目录里 748 道菜，官方配图只覆盖很少一部分。剩下的大头交给同学：拍一张、传一张，就能把这道菜补全，同时拿到积分。

## 一、菜品配图规则

- 一张照片只配一道菜。同一类关键词（比如「面」）只挑**菜名最短、最具体**的那道菜配图，其余菜品显示绿色占位底图 +「拍照上传」按钮。
- 这样不会出现「宫保鸡丁」的图被十几道菜共用的情况；对不上的菜宁可空着，也不拿别的菜凑数。
- 同学上传的实拍图优先级最高，会覆盖自带示意图，角标显示「同学实拍」。

## 二、上传流程

1. 菜品卡左下角点「拍照上传」，或在菜品详情里点「拍照上传」。
2. 手机直接调起相机（`capture="environment"`），也可以从相册选。
3. 浏览器端先压缩：长边 1280px、JPEG 质量 0.82，通常 100–300 KB。
4. 服务端校验：必须是 JPG/PNG/WebP（按文件头判断，不信扩展名），不超过 2 MB。
5. 存到 `DATA_DIR/uploads/dish-<sha1前16位>.<ext>`，写入 `db.json` 的 `dishPhotos`。

## 三、积分规则

| 行为 | 积分 | 每日上限 | 说明 |
| --- | --- | --- | --- |
| 首次上传某道菜的实拍图 | +20 | 100 分 | 同一道菜只算一次 |
| 补充同一道菜的其他照片 | +5 | 100 分 | 已有图时再传算补充 |
| 点评一道菜 | +5 | 30 分 | 24 小时内重复评价同一道菜不重复计分 |
| 上报窗口排队 | +2 | 20 分 | 同一窗口 3 分钟内只算一次 |

另外有硬性频率限制：同设备两次上传间隔 ≥10 秒，每天最多 20 张。

积分按设备标识（`localStorage` 里的 `cau-device-id`）记录，不需要注册登录；换设备或清缓存会重新开始。

## 四、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dish-photos` | 全部已投稿图片：`{ photos: { dishId: { src, at, by } } }` |
| POST | `/api/dish-photo` | 上传图片：`{ dishId, dataUrl, deviceId }` |
| GET | `/api/points?deviceId=` | 我的积分、今日进度、最近记录、全站统计 |
| GET | `/uploads/<file>` | 图片文件本身 |

`POST /api/dish-photo` 返回体里带 `points` 与 `pointsView`，前端可以直接刷新角标，不用再请求一次。

## 五、数据落盘

- `db.json` → `dishPhotos`（菜品图）、`points`（积分、每日计数、最近 200 条流水）。
- 图片文件在 `DATA_DIR/uploads/`；`DATA_DIR` 在服务器上是 `/var/lib/nongcanguan`，systemd 已授权写入。
- 老版本 `db.json` 没有这两张表，启动时会自动补齐，不需要手工迁移。
